# Roadmap

QAJitsu is built in ten stages. Each stage ends with something that works end to end and can be shown,
and the trust layer (guard, verifier, statuses) grows **before** the features that depend on it.

- The `Stage:` field of each requirement is authoritative; the lists below are generated by `pnpm req:index`.
- Current position: [STATUS.md](STATUS.md).
- A stage is done when every `must` requirement listed for it is `implemented` (or its stage-specific criteria are ticked)
  and the "Done when" demo works.

## Stage 1 · Foundation

Monorepo, tooling, core types, the guard and the status model; fetching a ticket and its code.

**Done when:** `qj fetch DEMO-1` writes `context/` (ticket, linked PRs/MRs, diffs, repos at the change's commit) into a new run folder;
`pnpm verify` is green in CI; adversarial tests for the guard and the status model block merges.
