# Glossary

| Term                  | Meaning                                                                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Run                   | One execution of the pipeline for one ticket; has a unique run id and its own folder in `<project-home>/runs/<TICKET>/<RUN_ID>/`.             |
| Run id                | `YYYYMMDD-HHMM-xxxx` (e.g. `20261003-1425-k3f9`); also used as the data marker (`qa-<ticket>-<run>`) on test data and runtime resources.      |
| Stage (pipeline)      | A step of a run: fetch, analyse, plan, approve, env, author, check, execute, verify, report, publish, cleanup.                                |
| Stage (roadmap)       | One of ten build stages of QAJitsu itself, see [roadmap](roadmap.md). Requirements carry `Stage: N`.                                          |
| Plan                  | `plan.vN.yaml`: test cases with steps, expected values and sources. Versioned on every revision.                                              |
| Approved plan         | `plan.approved.yaml`, frozen with a SHA-256 hash. Nothing outside it executes (INV-3).                                                        |
| Case                  | One test case of the plan (`TC-01`); gets exactly one status per run.                                                                         |
| Spec                  | Executable test generated by the author agent from the approved plan.                                                                         |
| `step()` / `verify()` | Functions from `@qajitsu/steps` that structure a spec, record evidence and assertions. Expected values come from `plan.expect(...)`.          |
| Runner                | Deterministic executor: Playwright (API, web) or WebdriverIO + Appium (mobile). The status comes from its output.                             |
| Evidence              | Request/response pairs, screenshots, videos, traces, logs; listed with hashes in `evidence/manifest.json`.                                    |
| Matrix                | Table of cases × status × evidence links, computed from results (INV-6).                                                                      |
| Guard                 | Code wrapped around every agent tool call: default-deny, write bans, URL allowlist, journal.                                                  |
| Journal               | `journal/events.jsonl`: append-only log of tool calls, steps and human actions.                                                               |
| Gate                  | A check that must pass before publishing (every case has a status, plan unchanged, evidence complete, no secrets...).                         |
| Auditor               | Agent that reviews PASSED results against evidence; may only downgrade to NEEDS_REVIEW (INV-5).                                               |
| Healer                | Agent that fixes selectors and waits in failing UI specs; cannot touch assertions (INV-4).                                                    |
| Canary                | Deliberately broken expectation run alongside real cases to prove the tests can fail (REQ-VER-09).                                            |
| Assertion lock        | AST diff that rejects changes to `verify()` calls between the authored and healed spec.                                                       |
| Adapter               | Package implementing a core interface (TicketSource, CodeHost, EnvProvider, SecretProvider, Runner, EvidenceStore, Publisher, ModelProvider). |
| Environment profile   | Named environment from `.qa/envs/` (base URL, allowlist, accounts) or a `--build` recipe.                                                     |
| Account alias         | `user:standard` style reference to a test account; credentials are resolved and used only inside framework login helpers (INV-8).             |
| `secret://`           | Reference to a secret resolved by a SecretProvider, e.g. `secret://env/JIRA_TOKEN`.                                                           |
| Role (model)          | analyst, planner, author, healer, auditor, summary; each mapped to a `<provider>/<model>`.                                                    |
| Capability profile    | What a model can do (tools, structured output, vision, context size); checked against role requirements.                                      |
| demo-shop             | The fictional app in `examples/demo-shop` with seeded bugs used to test QAJitsu itself.                                                       |
| INV-n                 | Architecture invariant n in `.claude/rules/architecture-invariants.md`.                                                                       |
| REQ-AREA-NN           | Requirement id in `docs/requirements/`. `REQ-X-NN/ACk` points to one acceptance criterion.                                                    |
| ADR-nnnn              | Architecture decision record in `docs/adr/`.                                                                                                  |
